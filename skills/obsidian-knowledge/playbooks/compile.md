> ⛔ 本 playbook 所有 vault 操作必须走 Obsidian Local REST API（`curl → https://127.0.0.1:27124`）。禁止用 Read/Write/Edit/Grep 直接访问 `knowledge/` 笔记文件——详见主 `SKILL.md`「⛔ 硬性约束」。

# Playbook: compile

**子命令**：`/obsidian-knowledge compile <URL|path>`

**定位**：深度编译外部文档为结构化笔记。含实体提取、关联检测、SHA256 增量。与 `/import`（快速捕获）互补——`/import` 轻快落 Inbox；`/compile` 深度分析落**领域目录**，带来源与摘要。

**前置**：读完主 `SKILL.md`。

---

## 编译流程

```
Step 1: 输入解析（URL / 本地文件 / 剪贴板）
Step 2: 增量检测（SHA256 比对 → 已存在则跳过或标记更新）
Step 3: LLM 链式分析
  Step 3a: 实体 / 关联 / 矛盾提取
  Step 3b: 结构化笔记生成
Step 4: 与现有知识交叉检测
Step 5: 生成笔记（含 SHA256 标记和来源信息）
Step 6: 人工审核确认（不自动写入）
```

---

## Step 1: 输入解析

支持：
- URL → WebFetch
- 本地文件 → Read
- 剪贴板 → 用户粘贴

---

## Step 2: 增量检测

编译前检查源文档的 SHA256 hash：

| 状态 | 行为 |
|------|------|
| 某领域已有同主题条目 SHA256 与本次一致 | 标记 **unchanged**，跳过编译 |
| SHA256 不同 | 标记 **changed**，建议更新 |
| 无已有条目 | 标记 **new**，执行完整编译 |

SHA256 hash 存储在笔记 frontmatter 的 `source_sha256` 字段：

```yaml
---
type: note
status: active
created: 2026-07-25
tags: [科研/论文阅读]
source: https://...
source_sha256: a1b2c3d4e5f6...
---
```

### SHA256 计算

```bash
# URL: 下载内容后 hash
curl -sL "$URL" | sha256sum | cut -d' ' -f1

# 本地文件
sha256sum <file> | cut -d' ' -f1
```

---

## Step 3: LLM 链式分析

### Step 3a: 实体提取

从源文档中提取：

| 提取项 | 说明 | 示例 |
|--------|------|------|
| 关键实体 | 核心概念、架构模式、设计决策 | PagedAttention，连续批处理，KV Cache |
| 实体类型 | 分类标签 | 架构模式，优化技术，数据结构 |
| 实体关联 | 实体间关系 | PagedAttention → depends-on → KV Cache |
| 矛盾检测 | 与已有知识冲突的点 | 与本领域约定不一致之处 |
| 适用性评估 | 对本知识库的价值判断 | 适用/部分适用/不适用 |

### Step 3b: 结构化生成

先复制 `_meta/templates/笔记模板.md` 作骨架，再填充：

```markdown
---
type: note
status: active
created: <today>
tags: [科研/论文阅读]
source: <URL>
source_sha256: <hash>
---

# <标题>

> 来源：[<title>](<URL>)
> 作者：<author>
> 发布日期：<date>
> 收录日期：<today>
> SHA256：<hash>

## 摘要

<1-2 段核心内容>

## 关键实体

| 实体 | 类型 | 说明 |
|------|------|------|
| ... | ... | ... |

## 实体关联

- EntityA → relation → EntityB
- ...

## 与现有知识的关联

- 与 [[xxx]] 相关（重叠/补充/矛盾）
- ...

## 适用性评估

<对本知识库的价值判断>
```

---

## Step 4: 交叉检测

编译结果需与现有知识执行交叉检测：

1. **关联检测**：提取的实体是否在 `<领域>/` 已有笔记中有对应概念
2. **重复检测**：与已有笔记的主题重合度
3. **矛盾检测**：与现有标准/约定的冲突

实现：

```bash
# 对每个提取的实体/关键词，简单搜索
curl -X POST "https://127.0.0.1:27124/search/simple/" \
  -H "$AUTH" -H "Content-Type: application/json" \
  -d '{"query": "<entity>"}'
```

输出交叉检测结果：

```
┌──────────────────────────────────────────────────┐
│ 交叉检测结果                                      │
├──────────────────────────────────────────────────┤
│ 关联：10-科研/算子空间理论/xxx.md ← 实体重叠     │
│ 重复：10-科研/算子空间理论/yyy.md ← 20%         │
│ 矛盾：无                                         │
└──────────────────────────────────────────────────┘
```

### 领域判定

基于交叉检测结果，判定新笔记应归属的领域与单元：
- 与某领域下的笔记高度关联 → 归入该领域对应单元
- 无明确关联 → 询问用户或暂放 `00-inbox`

---

## Step 5: 生成规范

生成的笔记必须：

- **来源归属必填**（来源/作者/发布日期/收录日期）
- **SHA256 必填**（用于增量检测）
- **关键实体表**（提取的核心概念）
- **关联表**（实体间关系）
- **交叉检测摘要**（与现有知识的关系）
- **适用性评估**（对本知识库的价值）
- **Wikilink 相关笔记**（至少 1 个 `[[xxx]]`）
- **标签两级且以领域开头**（`#科研/...` 等）
- **文件名中文自然命名**（禁止 kebab-case）

---

## Step 6: 人工审核

编译完成后**不自动写入**，而是：

1. 展示编译结果的完整 Markdown
2. 展示交叉检测结果
3. 提供操作选择：

```
📋 编译完成：<中文名>.md

操作选择：
  [W] 写入 <领域>/<单元>/（推荐）
  [E] 编辑后写入
  [S] 跳过（不写入）
  [U] 更新已有条目（如已存在同主题文档）
```

只有用户明确确认后才执行写入。

写入时走 `/write` 的原子 move + `_MOC.md` 更新 + 反向链接扫描流程。

---

## 使用方式

```
/obsidian-knowledge compile <URL或路径>    # 编译外部文档
/obsidian-knowledge compile --check        # 检查全库带 source_sha256 的笔记，源是否变更/可达
/obsidian-knowledge compile --dry-run <URL> # 预览编译结果但不写入
```

### `--check` 模式

扫描全库 `source_sha256` 字段非空的笔记：

1. 读取 frontmatter 的 `source` 和 `source_sha256`
2. 重新下载/读取源内容，计算当前 SHA256
3. 比对：
   - 一致 → ✅ unchanged
   - 不一致 → ⚠️ changed，建议重新编译
   - 源不可达 → ❌ source lost
4. 输出汇总：

```
📋 笔记增量检查

扫描：12 条
✅ unchanged：9 条
⚠️ changed：   2 条
  - 10-科研/算子空间理论/xxx.md（source SHA256 变化）
  - 10-科研/算子空间理论/yyy.md（source SHA256 变化）
❌ source lost：1 条
  - 10-科研/算子空间理论/zzz.md（404）
```

## 约束

- **禁止自动写入**：编译结果必须经人工确认后才写入
- **SHA256 必填**：所有编译生成的条目必须包含 source_sha256
- **来源归属必填**：外部来源必须有完整来源信息
- **交叉检测必做**：编译后必须执行与现有知识的交叉检测
- **增量优先**：已有条目 SHA256 不变则跳过，避免重复编译浪费 token
- **工具中立**：编译内容不得绑定特定平台专有语法
- **中文自然命名**：文件名见名知义，禁止 kebab-case / 纯英文
- **Wikilink 必填**：至少链接 1 篇相关笔记或 `_MOC.md`
- **标签两级且以领域开头**
